# Agent instructions — Pocket Archive

- **Top-level task: `MASTER-TASK.md`.** Read it before implementing anything, then `CODEX-BRIEF.md`, `README.md`, `DESIGN-SPEC.md`, `AI-BATCH-SPEC.md`.
- This is an existing functioning PWA. Preserve data/migration compatibility and existing completed work; refactor only for demonstrated need.
- **Claude cloud routine exception:** when running as the cloud organize task (triggered with `export_id=… attempt=…`), follow `CLAUDE-ROUTINE.md`, which takes precedence: no branch, commit, push or PR, and no Drive connector.
- **Execution contract:** deliver all feasible features in one autonomous task, with self-run automated tests and a single final reviewable PR/branch. Do not stop after a plan or first feature; do not require user approval at every development milestone. Follow `MASTER-TASK.md` acceptance tests.
- Devices: **iPhone / iOS Safari + home-screen web app and Windows**. No Android-specific features unless separately requested.
- Brand: **Pocket Archive**, Minimal & Modern, Butter Yellow `#FFF2C9` × Periwinkle `#CBD7EF`, **A3 solid bookmark Icon**. Icon selection is final for now; do not reopen design exploration.
- AI categorization is **initiated by the user pressing「送出整理」** and runs as a **Claude cloud scheduled task (routine)** on the user's Claude subscription — no separate paid AI API. The Worker records the job, fires the routine with `export_id`/`attempt` only, lets the routine fetch the batch and submit the result through the scoped agent API, validates it, and writes the App-created `AI-Results` placeholder in place. It never runs a model in the PWA, never uploads before the user initiates the job, and results are applied only after the user previews and selects them. Routine instructions: `CLAUDE-ROUTINE.md`; setup: `CLOUD-AI-SETUP.md`; design: `docs/superpowers/specs/2026-11-14-cloud-ai-routine-design.md`. The Windows local file flow (download batch → Claude Code → import organized.json) remains the fallback.
- Legacy (Codex): the phrase **「整理 Pocket Archive 最新的待整理收藏」** and the connector-based in-place Drive overwrite in `CODEX-DRIVE-WORKFLOW.md` are retired in favour of the cloud routine; keep the document for reference only.
- Never commit private exports/images, tokens or credentials. Do not publicly deploy, delete user data, start paid services or access private accounts without authorization. Work around blocked external operations and document the necessary user action at the end.
- Test in browser or automate where possible, explain any untested iOS device-only steps, keep a concise final manual UAT checklist. No claims of successful tests without executing them.

- Content-first classification: read [CODEX-CONTENT-EVIDENCE.md](CODEX-CONTENT-EVIDENCE.md), attempt actual source reading per item and generate a validated evidence receipt before tagging. `metadata_only` must be `insufficient_data`; do not infer video text from oEmbed title. When network capability is absent, fail closed without guessing. Preserve no-extra-AI-API workflow.
- AI startup must follow the batch-specific export_id (and attempt, for the cloud routine). Read CODEX-ORGANIZE-PROMPT.md and CODEX-CONTENT-EVIDENCE.md first. Never search Notion or other private workspaces. Missing Drive raw JSON/ZIP download, in-place content update, or read-back capability is a fail-closed blocker; never substitute another source or create a replacement result file.

## Executing agents other than Codex (Claude Code, v2.4.x docs)

- Wherever these documents say "Codex" for running a batch, reading sources or producing `organized.json`, they mean **the executing agent**, including Claude Code. File names (`CODEX-*.md`), schema, export_id binding, evidence rules and fail-closed limits are unchanged. Agent-specific notes live in `CLAUDE.md` and the "Claude Code" sections of `CODEX-DRIVE-WORKFLOW.md` / `CODEX-CONTENT-EVIDENCE.md`.
- **Capability is checked per connector, not per agent brand.** Before claiming the Drive exchange, the agent must confirm from its actual tool definitions that it can (1) download raw JSON/ZIP by file ID, (2) replace the **content** of an existing file while keeping its file ID, and (3) read the bytes back. A metadata-only `update_file` (title/parent/star/lock) does not satisfy (2).
- If (2) or (3) is missing, the Drive exchange is a fail-closed blocker: leave the `organized-<export_id>.json` placeholder untouched (still `pending`), never create a replacement result file, and report the missing capability. The agent may then, **only after the user agrees in chat**, use the existing local-file flow: write the validated result to `private-data/organized-<export_id>.json` (git-ignored) for the user to import with the App's「匯入 organized.json」. Report it explicitly as "local handoff, not automatic Drive exchange".
- Private batch data, evidence logs and results go under `private-data/` only. Never paste raw collection content into commit messages, PRs, issues or external search/skill queries.
- Project skills stay in `.agents/skills/` (Claude Code does not auto-discover this folder; read the listed `SKILL.md` directly). When a globally installed skill of the same name exists, the project copy pinned in `skills-lock.json` takes precedence for this repository.
